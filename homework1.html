4. Discussion

Based on running the numbers in the experiment above (default G = (1,5), so k = 1 to 8), here is what stands out:

  • One-way nature: Going from the private key k to the public key Q is super fast. But going backwards (finding k just by looking at Q) is the famous ECDLP problem, which is what actually keeps the whole system secure.
  • Distribution: Over one full period (k = 1 to 8 for G = (1,5)), the multiples hit each point of the subgroup generated by G exactly once. That is 8 of the 17 points of the curve. The bit statistics are visibly uneven (for example bit 4 of x is never 1), because the values only go up to 16 and 17 is not a power of 2. With a 256-bit prime this effect is negligible.
  • Correlation: For G = (1,5) the correlation between k and x is 0.00 and between k and y is about 0.30. With only 8 points this is not meaningful, and no simple pattern should be expected: the output is periodic with period n and follows an algebraic rule.
  • The Avalanche Effect: Flipping one bit of k changes about 46% of the output bits, which looks like a hash-style avalanche. But with only 8 points, any two different outputs differ in about half of their bits by chance, so this number says little here. More importantly, avalanche is not a design goal of scalar multiplication: neighbouring outputs are related by a simple public rule, (k+1)G = kG + G, which a good hash must not have.
  • Conclusion: So, for a cryptographic one-way function like this curve, the only things that matter are being deterministic, easy to compute forward, and basically impossible to reverse. Features like the avalanche effect and fixed output lengths are jobs meant for hashing algorithms (like Keccak).
